# Contributing

## Workflow

1. Select a task from [BACKLOG.md](BACKLOG.md) and create an issue with acceptance criteria.
2. Agree on an owner and reviewer.
3. Use a focused branch such as `feature/session-runner`.
4. Open a pull request explaining the problem, change, validation, and limitations.
5. Obtain peer review. Request professor review for study design, participant data, and support procedures.

## Issue template

Title / purpose / scope / artifact / acceptance criteria / dependencies / proposed owner / review needs. Use fictional examples and cite evidence where available.

## Pull request checklist

- [ ] Scope matches the issue.
- [ ] Planned and implemented behavior are distinguished.
- [ ] Appropriate checks and results are recorded.
- [ ] Documentation and version identifiers are updated.
- [ ] No credentials, student records, or sensitive conversations.
- [ ] Peer review complete.

## Validation and research integrity

Test meaningful behavior and failure cases. Check curriculum answers and objective alignment. Check documentation links and consistency. Use versioned model scenarios; one successful conversation is insufficient.

Do not invent citations or results. Record changes to hypotheses, outcomes, and analysis. Distinguish exploratory analyses from prespecified ones. Licensing, authorship, and institutional ownership need team agreement.
